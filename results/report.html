PROJECT MIZAN · v0.2.0 · results report

A hard constraint holds where a soft one gives way

Everything below was computed by python -m mizan.benchmark from fixed seeds. It tests one narrow claim about optimisation. It is not a test of AI safety.

1. Hard barrier versus soft penalty

A task pulls a parameter vector toward a target that lies outside a safe region (the unit ball). One method adds a fixed-weight penalty for leaving the region, which is the shape of a learned preference. The other uses an interior-point log-barrier that keeps every iterate strictly inside. We raise the optimisation pressure on the task and measure how far each method ends up outside the region.

The penalty's overshoot grows with pressure and approaches the full distance to the target. The barrier is never outside, and its distance to the true constrained optimum shrinks as the barrier strength rises, so it is not simply staying far from the wall.

2. Gate response to a controlled shift

Synthetic observations are generated with a known amount of variance on the coordinate the placeholder readout treats as unaligned. The gate trips more often as that variance grows (200 runs per point).

3. Cost

Median 8.9 ms, 99th percentile 10.1 ms, about 113 evaluations per second per core (200 runs). The service is stateless, so throughput scales with the number of containers.

What this does not show

  • Experiment 1 is a mathematical illustration on a convex toy problem with a known safe region. It supports the narrow claim that a barrier method keeps iterates inside a constraint set that a fixed-weight penalty does not. It does not show that any real model's behaviour can be expressed as such a constraint.
  • Experiment 2 uses data labelled by construction. It shows the gate arithmetic responds in the expected direction. It is not a detection rate on real inputs.
  • The gate is uncalibrated, reads no real model, and does not understand text. No external review or benchmark has been done.
  • The soft-penalty baseline uses one weight (100). A larger weight delays the overshoot but does not remove it, and an exact-penalty method would behave differently.
