Five stages, from the core hypothesis to a real model to verification. Everything on this page is computed by the running service or read from files it produced. Nothing is mocked.

Read first. This is a concept demonstration. It tests whether a hard constraint holds under optimisation pressure. It does not show that any model is safe, the gate is uncalibrated, and its telemetry is synthetic.

Stage 2 · monitor

The safety gate

The service reads a state matrix, computes an alignment value, spread, entropy and a Monte Carlo robustness estimate, and combines them into a margin. The input here is deterministic synthetic telemetry seeded from the text, so the text itself is not analysed.

Benchmark

Fixed-seed experiments from python -m mizan.benchmark: 30 random problems across 6 pressure levels, the gate's response to a controlled shift, and cost. Open the full report.

Stage 4 · real model

Phase 1: Pythia-160M

Same question on a real 160M-parameter model: only the final LayerNorm (1,536 numbers) is trained to lower loss on a fixed style, while a KL trust region around the original behaviour is the constraint. The pass/fail criteria were written before any results.

Stage 5 · verification

Test suite

Runs the full pytest suite on the machine hosting this service. Disabled on shared deployments.

What this does not show

  • The wall experiment is a convex toy problem. It supports a claim about optimisation, not about real model behaviour.
  • The gate is uncalibrated and reads synthetic data. Its trips are not detections.
  • The real-model run is one model, one small parameter slice and one synthetic constraint. The constraint is a trust region, not an ethical principle.
